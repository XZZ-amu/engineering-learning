# P2-3：安全基础 — 内容安全、API 防滥用、用户数据保护

---

## 1. 一句话本质

**AI 创作产品的安全问题，本质是"低成本批量生成"带来的失控风险——你给用户一把枪，就必须想好谁能用、用多少、打出去的子弹能不能收回来。**

普通 Web 产品的安全问题，主要是"坏人入侵"。AI 创作产品多了一类问题：**正常用户也可能用正常功能造成大规模伤害**。一个人一天能生成一万张图，这在传统产品里不存在。这句话能推导出后面所有防护逻辑。

---

## 2. 为什么必须这样

假设 Mindloop 上线了一个 AI 生成插图功能，没做任何安全设计。会发生什么？

**第一周：** 有人批量生成色情图片，上传到公开笔记里。
**第三天：** 有人写脚本，每秒调用 50 次你的生成接口，你每次调用都要付 OpenAI 的钱。
**第二周：** 有人注册 200 个账号，全部领取免费试用额度。
**一个月后：** 一位用户发现你把他的私人笔记内容发给了第三方审核员，他要求你删除所有数据，你不知道数据在哪、怎么删。

这不是极端情景，是 AI 产品上线第一个月的标准遭遇。安全不是"上线后再说的事"，是产品设计阶段就要埋进 PRD 的需求。

---

## 3. 概念地图

```
"低成本批量生成"带来的失控风险
          │
          ├── 内容失控（生成了不该生成的）
          │         │
          │         ├── NSFW 检测（拦截坏内容）
          │         ├── 审核流程（先审/先发的取舍）
          │         └── 举报处置（漏网之鱼的兜底）
          │
          ├── 资源失控（有人在薅你的钱）
          │         │
          │         ├── Rate Limiting（限制速度）
          │         ├── 防爬虫（识别机器行为）
          │         └── 防薅羊毛（识别多账号）
          │
          └── 数据失控（用户数据不在你掌控里）
                    │
                    ├── 隐私设置（谁能看）
                    ├── 传输/存储加密（传输过程中不被偷）
                    └── GDPR（用户有权让你删）
```

三条线，每条线都是"生成能力失控"在不同维度的表现。防护思路也各不相同：内容问题靠**检测+流程**，资源问题靠**计量+限制**，数据问题靠**隔离+加密+删除权**。

## 4. 逐个概念深入

### 内容安全

#### NSFW 检测：为什么不能只靠模型自己

模型（比如 Claude、DALL·E）本身有安全过滤，为什么还要自己做检测？

因为**模型的过滤是面向全球用户的最低公约数，你的产品有自己的尺度**。更重要的是：模型的过滤是在"生成前"阻止，但用户自己上传的图片、修改的标题、写的注释，模型管不着。你的审核要覆盖**所有进入系统的内容**，不只是 AI 生成的部分。

NSFW 检测本质是一个分类器：给它一段文字或一张图，它返回"安全/不安全/可疑"的概率分值。你设定阈值，超过就拦截或送审。

**Tradeoff：** 阈值低，漏过坏内容；阈值高，误伤正常用户（一张艺术人体画被判违规）。这个阈值不是技术问题，是**产品价值观决策**，需要你来定。

#### 审核流程：先审后发 vs 先发后审

```
先审后发：用户生成 → 等待审核 → 发布
先发后审：用户生成 → 立即发布 → 后台审核 → 问题内容下架
```

**先审后发**：安全，但用户体验差。生成一张图还要等几分钟审核，用户流失。适合：高风险场景（未成年人平台、公开社区首页）。

**先发后审**：体验好，但有时间窗口——坏内容在被下架前已经被人看到了。适合：低风险场景（私人笔记、小圈子分享）。

Mindloop 的私人笔记可以先发后审，公开发布到社区的内容可以先审后发。**同一个产品可以对不同场景用不同策略**，这是 PRD 里要明确写的。

#### 举报处置：漏网之鱼的兜底

审核不是 100% 准确的。举报系统是**用户帮你做最后一道检测**。

设计要点：
- 举报后内容**不应立即下架**（防止恶意举报攻击竞争对手），应进入审核队列
- 高频举报或严重类别（儿童安全）应触发自动临时隐藏
- 举报者要收到结果反馈，否则用户会放弃举报

### API 防滥用

#### Rate Limiting：令牌桶算法

为什么要限速？不是怕用户用太多，是怕你**付不起**。每次调用 AI 都有成本，不限速等于给攻击者一张无限额信用卡。

**令牌桶算法**（水龙头类比）：

```
桶子 = 用户的配额（比如 5 个令牌/天）
水龙头 = 按固定速率往桶里加水
用户每次请求 = 从桶里取一个令牌
桶空了 = 请求被拒绝，提示"今日额度已用完"
```

关键设计点：**令牌是按时间补充的，不是一次性给满的**。这样能防止用户一开始就把 5 次全部瞬间打完。

Mindloop 免费用户 5 次/天怎么实现：
- 每天 0 点往每个用户的桶里加 5 个令牌
- 每次调用生成接口前，先检查桶里有没有令牌
- 有令牌 → 扣一个，放行；没有 → 返回"429 Too Many Requests"，前端提示升级

这个逻辑不需要你写代码，但**要在 PRD 里写清楚**：免费/付费各多少次、按天还是按月、超出后的提示文案是什么。

#### 防爬虫 vs 防薅羊毛：两个不同的问题

**防爬虫**：识别"这个请求是机器发的"。手段包括验证码（摩擦成本）、行为检测（正常用户点击有轨迹，机器直接调接口没有）、请求速率异常（1 秒 50 次请求，人类做不到）。

**防薅羊毛**：识别"这是同一个人的第 N 个账号"。爬虫在乎速度，薅羊毛的人注册速度可以很慢、行为完全正常，但就是在重复领免费额度。手段：手机号验证（一个号一个账号）、设备指纹（同一台设备多次注册）、支付卡绑定。

两者防护手段**不同**，PRD 里要分开写需求。

### 数据保护

#### 隐私设置：三级结构

```
私有（只有我能看）
  └── 仅链接可见（有链接的人能看，但搜索不到）
        └── 公开（所有人可见，可被搜索）
```

这三级的区别不是"可见范围"，是**主动发现 vs 被动访问**的区别。"仅链接可见"的内容，不会被搜索引擎收录，不会出现在推荐流，但如果你把链接发给别人，他们能看到。这对产品分享功能设计影响很大——分享链接时要提示用户当前的隐私级别。

#### 传输加密 vs 存储加密：两道门

```
用户 ──HTTPS──> 你的服务器 ──加密存储──> 数据库
     (传输加密)              (存储加密)
```

**HTTPS（传输加密）**：数据在路上不被截获。现在是标配，没有 HTTPS 浏览器直接报红色警告。

**存储加密**：数据库被黑客拖库了，拿到的是乱码不是明文。对 AI 创作产品最关键的是**用户生成的作品文件和 prompt 记录**——这些可能包含用户的私人想法，泄露出去很敏感。

两者都必须有，缺一不可。传输加密防"路上被偷"，存储加密防"仓库被砸"。

#### GDPR：用户有权让你消失

GDPR（欧盟数据保护条例）的核心是一条权利：**用户可以要求你删除所有关于他的数据**。

对 AI 创作产品，麻烦在于：用户的数据可能散落在——数据库、对象存储（图片文件）、日志、AI 训练集、备份。如果设计阶段没想好"用户数据在哪里"，收到删除请求时会一团乱。

设计时需要明确：用户数据的**数据地图**（存在哪、存多久）、删除操作的**级联效果**（删用户时关联的作品、评论、生成记录是否一并删除）。这不是研发自己能决定的，是**产品需要在 PRD 里定义的数据策略**。

## 5. 研发在争什么

**争 1：内容审核要不要人工参与**

纯机器审核：快、便宜，但误判多，漏过边缘内容。人工审核：准，但贵、慢、还涉及审核员的心理健康问题。争论焦点是**成本和精度怎么平衡**，以及一旦出事，"机器误判"和"人工放过"哪个法律责任更小。

**争 2：Rate Limiting 要不要区分 IP 还是账号**

按账号限制：用户换 IP 没用，但如果是企业内网（同一 IP 多人用），会误限。按 IP 限制：能防未登录的批量请求，但攻击者换 IP 就绕过了。通常答案是**两者叠加**，但具体阈值怎么设，每个产品不同。

**争 3：存储加密到什么程度**

全部内容加密：最安全，但查询性能下降（加密内容不能全文搜索）。部分加密（只加密敏感字段）：平衡性能，但要定义什么是"敏感"。对 AI 创作产品，用户的 prompt 算不算敏感？这是产品价值观问题，技术只是执行。

## 6. 生成 → 审核 → 发布：一套完整流程

```
用户发起生成请求
       │
       ▼
[Rate Limiting 检查] ──超限──> 返回 429，提示升级
       │通过
       ▼
[模型生成内容]
       │
       ▼
[NSFW 检测] ──高风险──> 直接拦截，记录日志
       │低风险/可疑
       ▼
   [风险分级]
   可疑内容 ──────────────────> [人工审核队列]
       │安全                          │
       ▼                             ▼
[用户可见，标记"已发布"]    [审核通过] → 保持可见
                           [审核拒绝] → 下架 + 通知用户
       │                          
       ▼（用户选择公开分享）
[再次 NSFW 检测，更严格阈值]
       │通过
       ▼
[公开发布，进入举报系统监控]
```
