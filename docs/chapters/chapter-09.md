# P1-1: AI 工程基础 — 模型调用、prompt 结构、采样参数、工作流

## 1. 一句话本质

**AI 生图的本质，是在一个巨大的"视觉可能性空间"里导航——prompt 决定目的地，参数决定走法，模型决定你能去哪儿。**

从这句话可以推导出所有东西：为什么 prompt 要精确描述（目的地模糊就会迷路）、为什么参数会影响结果（走法不同到的地方不同）、为什么不同模型有不同能力（地图范围不一样）、为什么要工作流（一次导航不够，要多段接力）。

---

## 2. 为什么必须这样

想象你走进一家摄影棚，想拍一张"赛博朋克风格的女孩坐在霓虹灯下"的照片。

如果你只说"拍个女孩"——摄影师不知道怎么打光、穿什么衣服、背景用什么。  
如果你说了所有细节，但摄影师手上只有一台傻瓜相机——再好的描述也没用。  
如果摄影师很厉害，但你让他"随便拍拍，差不多就行"——每次结果都不一样，没法复现。

AI 生图遇到的是同一批问题：
- **没有 prompt 结构**：模型不知道哪些描述重要，输出随机
- **不懂采样参数**：同一个 prompt，steps 不够图就糊，cfg 太高就崩
- **不知道用哪个模型**：用基础模型做风格迁移，结果总是不对
- **没有工作流**：每次手动调，无法复现，无法批量

这些不是规矩，是被实际失败逼出来的解法。

## 4. 逐个概念深入

### 模型调用：输入→推理→输出，GPU 为什么贵

调用一次模型，本质上是：把你的 prompt 编码成向量，在噪声图像上反复执行"去噪"运算，每一步都是大量矩阵乘法。

GPU 贵的原因不是它"高级"，是因为矩阵乘法本质上是几千个计算同时并行——CPU 只有几十个核，GPU 有几千个小核，专门干这个。  
一张 SDXL 图，RTX 4090 大概 3-5 秒，CPU 要跑 10 分钟。

**对你的意义**：生图的成本不在存储，在算力。所以 API 按张计费，而不是按文件大小。

---

### Prompt 结构：目的地要怎么描述

正向 prompt = 你要什么。反向 prompt = 你不要什么（常见反向：`ugly, blurry, low quality, deformed`）。

**权重语法**：`(赛博朋克:1.3)` 表示加权 1.3 倍，`[女孩:0.8]` 表示降权。不是所有词同等重要，权重让你告诉模型"这个更重要"。

**Prompt 模板设计思路**（以人物生成为例）：
```
[画质标签], [主体描述], [动作/表情], [场景/背景], [光线], [风格/媒介], [镜头参数]

示例：
masterpiece, best quality, 1girl, cyberpunk outfit, 
sitting, neon lights background, cinematic lighting, 
photorealistic, 85mm lens, shallow depth of field
```

这个结构不是规定，是经验：模型在训练时图文对的描述就是这个顺序，所以按这个顺序写，命中率更高。

**反向 prompt 有多重要**：没有反向 prompt，模型默认允许所有可能性出现。加了反向 prompt，等于给导航仪标了"禁止通行区"。

---

### 采样参数：走法控制

**Seed（种子）**：决定从哪个噪声点出发。固定 seed = 可复现结果。seed = -1 就是随机起点。  
→ 调参时先固定 seed，不然你不知道变化来自参数还是随机性。

**Steps（步数）**：去噪要走几步。步数少=图糊，步数多=收益递减（20步够用，50步以上边际效益很低）。  
→ 类比：雕塑家划几刀可以出形态，但划一百刀不会比五十刀好多少。

**CFG / Guidance Scale（相关性强度）**：控制模型有多"听话"。  
- CFG = 3：自由发挥，可能偏离 prompt 但更自然  
- CFG = 7：平衡点（常用默认值）  
- CFG = 15+：严格按 prompt，但容易过饱和、崩图  
→ 类比：摄影师执行指令的严格程度。太自由偏离需求，太严格反而失去审美。

**Sampler（采样器）**：去噪路径的算法。DPM++ 2M 快而稳，Euler a 有随机性，DDIM 适合精确控制。  
→ 大多数情况用 DPM++ 2M Karras 就行，不需要纠结，除非你在追求特定风格感。

**同一 prompt，参数对比**：

```
prompt: "1girl, cyberpunk, neon lights"

seed=42, cfg=7,  steps=20 → 正常人脸，光影合理
seed=42, cfg=15, steps=20 → 颜色过饱和，五官变形
seed=42, cfg=7,  steps=5  → 模糊，形态未收敛
seed=-1, cfg=7,  steps=20 → 每次不同，无法复现
```

"这张图不好"的诊断逻辑：  
- 图糊 → steps 太少或 cfg 太低  
- 颜色爆炸/五官崩 → cfg 太高  
- 跟 prompt 不搭 → 正向 prompt 描述不精确，或 cfg 太低  
- 无法复现 → seed 没锁定

---

### 模型类型：基础模型 vs LoRA vs ControlNet

这三个不是替代关系，是叠加关系：

**基础模型（SD1.5 / SDXL / FLUX）**：决定"你能去哪"的边界。训练数据越多越广，能生成的内容越丰富。选模型是选底层地图。

**LoRA（Low-Rank Adaptation）**：在基础模型上微调，只调"方向"而不重新训练整个模型。  
→ 用途：特定画风（水墨风 LoRA）、特定人物（明星/IP LoRA）、特定产品风格  
→ 类比：摄影师本人不变，但给他换了一套拍特定风格的滤镜+构图习惯

**ControlNet**：用额外的输入图（骨骼图、边缘图、深度图）控制生成结构。  
→ 用途：要求特定姿势、特定构图、图生图保持结构  
→ 类比：给摄影师一张参考图说"就按这个姿势拍"

什么时候用哪个：
- 想换风格 → 换基础模型或加 LoRA
- 想固定某个人/IP → 加对应 LoRA
- 想控制构图/姿势 → 加 ControlNet
- 三个同时用 → ComfyUI 工作流

---

### ComfyUI 工作流：为什么比单次调用强

单次调用：prompt → 图。  
工作流：图 → 放大 → 修脸 → 换背景 → 最终输出。

ComfyUI 是节点式编排，每个节点是一个处理步骤，节点之间用线连接传数据。

```
[Load Model] → [CLIP Text Encode] → [KSampler] → [VAE Decode] → [Save Image]
                                         ↑
                              [ControlNet Apply] ← [Load ControlNet]
```

**为什么节点式更强**：
1. 可复用：同一个工作流可以批量跑不同 prompt
2. 可调试：每个节点的输出都可以单独查看
3. 可组合：别人的工作流可以直接导入复用
4. 可自动化：接 API 就能程序化触发整条链路

→ 对产品设计师的意义：ComfyUI 工作流 = 你设计的生产流水线，不只是"出一张图"，而是"稳定出一类图"。

### 部署方式：自建 vs API

| | 自建 GPU | API 服务（Replicate / RunPod） |
|---|---|---|
| 成本结构 | 固定成本（机器/电费） | 按次计费 |
| 适合场景 | 高频调用 / 需要完全控制 | 低频探索 / 快速验证 |
| 启动难度 | 高（需配环境） | 低（一个 API key） |
| 模型自由度 | 完全自由 | 受平台支持模型限制 |
| 延迟 | 低（本地） | 有冷启动延迟 |

**实际建议**：产品原型阶段用 API，验证需求；量产阶段评估是否自建。不要一开始就买卡——需求没验证之前，固定成本是浪费。

## 5. 研发在争什么

**争一：FLUX 还是 SDXL？**  
FLUX 生图质量更高，但推理慢、显存要求高；SDXL 生态更成熟，LoRA 多。没有标准答案，看项目对质量 vs 速度的权重。

**争二：CFG 多少合适？**  
有人坚持 CFG=7 是黄金值，有人说特定风格要用 CFG=3。根本分歧在于：你要"听话的模型"还是"有创造力的模型"。这其实是产品决策，不是技术决策。

**争三：ControlNet 用多少条件？**  
条件越多越精确，但创意空间越小，生成越难看。骨骼+深度+边缘同时加，模型经常崩。取舍：精确性 vs 自然度。

**争四：工作流放大用什么节点？**  
Upscale 节点很多：Real-ESRGAN 适合写实，Anime4K 适合二次元，Latent Upscale 保留 AI 特征但可能糊。没有万能方案。
